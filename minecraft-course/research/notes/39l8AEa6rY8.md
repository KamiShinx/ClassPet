# Paper Mario: Color Splash's Combat (Design Doc, 11.8 min)

**What it is:** Video essay diagnosing why Color Splash's battle system feels bad: it kept the RPG genre's trappings (turns, HP, items) while stripping the systems (action-command variety, low/legible damage numbers, FP-based resource limits, build customization) that made those trappings meaningful in the older Paper Mario games.
**Substance:** substantive as a critique with specific, well-chosen examples, but it's entirely about turn-based menu combat feel (action-command timing, damage-number legibility, resource meters) — a genre this class's real-time sandbox mod doesn't share. The one durable idea is structural: don't keep a system's skin without its substance.

## Ideas, in the video's order
- [1:44] Classic Paper Mario's action commands (varied inputs: pull stick, hold button, aim/shoot) kept combat active; Modern Paper Mario reduced them to near-identical timed button presses, making every attack feel the same (generic "input variety" point).
- [2:54] Classic Paper Mario used small, legible damage numbers (2-3 for weak hits, 8 for strong) so players could do mental math on efficiency; Color Splash removed numbers entirely in favor of a color-drain visual, which looks nice but hides actual power differences between attacks.
- [6:11] Color Splash's "Paint" resource (replacing the old FP/Flower Points mana system) is so abundant and easy to refill that it stops functioning as a real limiter — a resource system with no real scarcity doesn't create the strategic tension it's supposed to.
- [8:30] Classic Paper Mario's badge system let players build very different playstyles (low-HP runs, no-jump runs, overpowered/underpowered builds); modern games removed meaningful build customization, leaving players with no real choices to express.
- [9:37] **Core thesis, stated directly**: "if you're going to change the system you need to end up with something compelling and rewarding" — ripping out core genre mechanics CAN work, but only if replaced with something that still gives players options and feedback; here it just made the game "hollow."

## What the frames add
Constant Color Splash gameplay clips with visible damage/HP numbers, action-command prompts, and card-inventory screens [throughout] make the "you can't tell attacks apart" critique concrete — e.g. seeing a weak jump attack repeat 5-6 times on a single enemy visually confirms the "no legible damage" complaint. A closing text card, "RIPPING OUT CORE GENRE MECHANICS CAN WORK" [11:15], is the cleanest single-sentence summary in the video.

## For our class (11-13, Minecraft mod, Gemini writes the code)
### Becomes something kids do
- **"What are you keeping vs. cutting?" sanity check (5-10 min, use when a kid wants to simplify a vanilla Minecraft system for their mod)**: if a kid wants to remove or simplify part of an existing Minecraft system (e.g., "my custom weapon doesn't need durability"), ask them what they're replacing that removed constraint WITH — nothing, or a new source of tension. Directly modeled on the video's core thesis; catches the specific failure mode of stripping depth without replacing it.

### Survives the move to Minecraft?
The general principle (cutting a system's substance while keeping its appearance leaves it hollow) is real and worth a line in a tooltip, but it's abstract design criticism, not a buildable mechanic — nothing here maps to a specific NeoForge feature the way other videos in this batch do.

### Doesn't transfer
Action-command timing (QTE-style button prompts during attacks), turn-based damage-number legibility, and FP-as-mana resource management are all turn-based menu-combat concerns with no equivalent in Minecraft's real-time combat, which already shows continuous HP bars, particle/knockback feedback, and hunger/durability as its resource systems.

## Honest caveats
This is a well-made critique but entirely about a genre (menu-based turn combat) this class isn't building. Only the closing thesis line is worth carrying forward, and it's generic enough that it doesn't need this video as a citation — treat it as a one-line caution, not a worksheet source.

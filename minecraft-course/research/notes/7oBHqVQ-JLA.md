# How do Game Designers make their games FUN? (Sasquatch B Studios, 7.4 min)

**What it is:** A solo dev-channel essay arguing fun is hard to measure, walking through the MDA framework's 8 "types of fun," then covering iteration/playtesting advice.
**Substance:** mixed: the MDA recap is a legitimate, citable framework, but roughly half the runtime is stock b-roll, a tangent on negative emotions, and generic playtesting advice repeated across many channels.

## Ideas, in the video's order
- [0:01:04] MDA (Mechanics/Dynamics/Aesthetics) framework's 8 categories of "fun": sensation, fellowship, challenge, fantasy, narrative, discovery, expression, submission. This is the same framework the earlier game-design batch already flagged as class-ready — nothing new here, just a second source confirming it.
- [0:02:11] Negative emotions (fear, frustration, sorrow) count as "fun" too if followed by relief/triumph — a useful reframe for horror/hard-boss design, but stated abstractly, no design technique attached (generic).
- [0:03:17] Worked example: applying the 8 categories to Ocarina of Time, Celeste, Hollow Knight, Stardew Valley to see which mix of categories each hits. This is the one genuinely demonstrable technique in the video.
- [0:03:48] Design-on-paper vs. design-in-engine gap: an idea that sounds fun in a doc can be un-fun once playable (jump-scare-every-corner example) (generic but true).
- [0:04:54] "Remove the unfun" principle (Scott Rogers/Pac-Man): start with a fun idea, and as you iterate, cut whatever tests as not-fun rather than only adding more (generic, widely repeated advice).
- [0:05:59] Match playtesters to the target audience; don't use your mom for a Soulslike (generic).
- [0:06:14] Other designers critique like designers, not like players — get feedback from both (generic).
- [0:07:03] Tiny tip: make objects breakable (Enter the Gungeon pots) — purely a "juice" tip, not a mechanic.

## For our class (11-13, Minecraft mod, Gemini writes the code)
### Becomes something kids do
- **"Fun-type checklist" worksheet (15 min)**: before speccing a mod feature, kid checks which of the 8 MDA categories it hits (sensation/fellowship/challenge/fantasy/narrative/discovery/expression/submission). If it hits zero, that's a flag to rethink. This duplicates what the earlier batch already proposed from GMTK/MDA sources — don't build it twice, just note this video as a second citation for the same worksheet.
- **"Remove the unfun" playtest pass (10 min, paired)**: after a kid's mod feature works in-game, a partner plays it and names the single most annoying/boring moment; kid fixes just that one thing. Cheap, concrete, reusable every week.

### Survives the move to Minecraft?
The MDA categories map fine onto vanilla Minecraft verbs (discovery = exploring caves, expression = building, fellowship = co-op survival), so kids can use it to sanity-check a mob or item spec. The "unfun removal" loop also survives — it's just "playtest your own gradlew runClient build and cut the annoying part."

### Doesn't transfer
The playtester-selection and dev-vs-designer-feedback advice assumes a studio with multiple playtesters and target-audience segmentation — not relevant to one kid building a solo mod feature for homework.

## Honest caveats
Nothing here contradicts other sources; it mostly restates MDA, which the class already has from elsewhere. The "negative emotions = fun" point is true but is asserted, not demonstrated with a technique — don't oversell it as a new design tool. Extrapolation: the worksheet idea above is mine, not the video's — the video does not propose any classroom activity.

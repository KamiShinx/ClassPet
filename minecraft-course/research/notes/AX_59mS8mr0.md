# What Makes A Game Replayable? (Design Doc, 20.3 min)

**What it is:** A three-category framework for replayability — Novelty (dev-provided new content), Creativity (player-driven sandbox/tools), Evolution (skill growth over time) — each paired with its own failure mode (Staleness, Inhibition, Stagnation).
**Substance:** substantive: a clean, symmetric 3x2 framework (three positive drivers, three matched failure modes) applied to a very wide range of genres; one sponsor read.

## Ideas, in the video's order
- [0:00:31] Core claim up front: replayability is independent of quality — a great game can be a poor replay, a mediocre game can be very replayable. (Sets up why this is its own design axis worth designing for deliberately.)
- [0:02:12] **Novelty** = the game itself provides new content on repeat plays: branching paths/side-objectives (Star Fox 64's mission branches), multiple endings, distinct character classes/builds (Bloodstained: Curse of the Moon's swappable allies), procedural generation (Hades, Spelunky, FTL — works best when a single run can't touch all possible content).
- [0:05:59] **Staleness** (Novelty's failure mode): rigid single storylines (Ace Attorney, cinematic games like Uncharted — sometimes a legitimate authorial choice, not always a flaw), rigid character progression with no experimentation (FFXIII), and — sharpest warning — **false choices**: branching dialogue that funnels back to the same outcome regardless of pick (Telltale games) permanently damages trust once players notice, retroactively souring a system they enjoyed before discovering the illusion [0:07:01].
- [0:07:38] **Creativity** = replayability sourced from the PLAYER, not the game: user-generated content/modding (Mario Maker, Skyrim mods) and self-contained sandboxes (Minecraft and Terraria explicitly named as "the gold standards" — freedom + tools + open space = build your own goals) [0:08:10]; "clockwork system" open worlds (BotW, MGSV, Hitman) where tasks have no single intended solution, so players invent their own approaches.
- [0:09:47] **Inhibition** (Creativity's failure mode): a dominant strategy saps the fun of creative problem-solving (MGSV's tranquilizer gun is so efficient it crowds out other approaches — fix suggested: add resource limits to force variety); reliance on external servers for UGC is fragile — when the service shuts down, replay value vanishes overnight (ModNation Racers cited as a game killed this way) [0:10:48]; open worlds that are big but empty (L.A. Noire) or that restrict players inside missions despite an open shell (Red Dead Redemption 2's insta-fail missions) undercut the freedom that was the whole draw.
- [0:12:21] **Evolution** = replayability from getting better at the game over time, "a give-and-take between player dedication and developer design": competitive multiplayer with real skill ceilings (Smash Melee's 20-year lifespan via emergent tech like wavedashing; Rocket League; even chess as the ultimate example of a static ruleset staying replayable through skill depth alone); single-player equivalents include high scores/leaderboards and ranking/grading systems (Devil May Cry, Bayonetta) that give immediate feedback on mastery.
- [0:15:05] Evolution can also be fan-driven, not dev-intended at all: speedrunning (finding skips devs never planned) and self-imposed challenges (Nuzlockes, no-coin Mario runs) push a game's depth further than its own design anticipated.
- [0:16:06] **Stagnation** (Evolution's failure mode): multiplayer games die without a sustained playerbase (bots are a poor substitute — they don't adapt); playerbases that skew too skilled become hostile to newcomers (fighting games named specifically); a single dominant strategy/character poisons a competitive meta (Brawl's Meta Knight, made worse because the game couldn't be patched) — "dominant strategies are poison to any competitive multiplayer game, just as much as they hurt single player games with clockwork systems," explicitly tying Evolution's failure mode back to Creativity's.
- [0:18:12] Final practical checklist question, explicitly framed as evergreen and genre-agnostic: **"for someone replaying a game, what aren't they replaying it for? Then figure out ways to reduce those things."** Cites heavy RNG (removes player agency over losses), unskippable cutscenes, and long forced tutorials as concrete "friction that kills replays" examples.

## What the frames add
Genuinely useful category-label text cards appear at multiple points — "NOVELTY / CREATIVITY" side by side at [0:00:45], "PROCEDURAL GENERATION" [0:02:45], "CREATIVITY" [0:07:30], "HIGH SCORES AND LEADERBOARDS" [0:13:45], "DIFFICULTY, CHALLENGE MODES AND RANKING SYSTEMS" [0:14:15] — together these work as a ready-made outline of the video's own structure, useful if we want to build a poster/worksheet with the same six-box (3 drivers + 3 failure modes) layout. Notably, actual **vanilla Minecraft building footage** appears at [0:08:30]-[0:08:45] (placing blocks, basic crafting/inventory UI) as the direct illustration of the Creativity/sandbox category — confirms the video considers Minecraft itself the textbook example of this category, which is directly relevant to us. Otherwise, wall-to-wall b-roll of named games, no diagrams beyond the text-card category labels.

## For our class (11-13, Minecraft mod, Gemini writes the code)
### Becomes something kids do
- **"Why would someone play this twice?" design check (10-15 min, run near the end of a kid's project)**: pick which of the three drivers (Novelty/Creativity/Evolution) their mod leans on most, and name ONE concrete thing that supports it (a random loot table = Novelty, a new sandbox tool/block = Creativity, a leaderboard/best-time = Evolution). This is a strong wrap-up framing question since Minecraft itself is explicitly the genre's Creativity poster child.
- **"No false choices" rule (5 min, generic but sharply anchored)**: if a kid adds player-facing choices (a custom villager dialogue, a "pick your path" structure), flag the Telltale problem directly — a choice that doesn't actually change anything will be noticed and will sour trust, so either make it matter or don't present it as a choice.
- **"What's the friction?" review pass (5-10 min, apply to any finished mechanic)**: use the closing checklist question directly — does using this item/beating this mob/visiting this structure involve annoying RNG, a forced unskippable step, or busywork nobody wants to repeat? Cut it.

### Survives the move to Minecraft?
This is the batch's clearest confirmation that Minecraft's OWN base design (sandbox creativity, open building, player-invented goals) is already the strongest replayability driver available to a kid's mod — so the most direct, low-effort thing a kid can do is lean into Creativity: add new build-able blocks, new crafting options, or new tools that let players invent their own goals, rather than trying to bolt on Novelty content (branching story, procedural dungeons) that's expensive to build in a school-year project. Evolution-style replayability (leaderboards, ranking/grading, speedrun-friendliness) bends existing systems lightly — a custom scoreboard objective (fastest boss kill, most blocks placed) is genuinely easy for Gemini to build via NeoForge + vanilla scoreboard/criteria hooks, and it's a good low-cost feature to add near the end of a kid's mod. True Novelty via procedural generation (a custom structure/dungeon generator) is a much bigger NeoForge ask — buildable, but a stretch-goal for an advanced kid, not a default recommendation.

### Doesn't transfer
The competitive-multiplayer Evolution examples (Smash Melee's decades-long metagame, chess) describe forces (huge live playerbases, professional-level community-driven tech discovery) entirely out of scope for an 8-kid single-mod-each class — cite the general "mastery over time" idea, not the multiplayer-scene mechanics behind it. The UGC/modding-server fragility warning (ModNation Racers) is a real caution for anyone SHIPPING a live game but not relevant to a classroom project with no server infrastructure.

## Honest caveats
Strong, clean framework — probably the second-most reusable structural idea in the batch after the Unlockables video's Criteria+Prize framework, and it should be cited directly in the batch synthesis, especially since it explicitly names Minecraft as the reference example for Creativity-driven replayability. One thing worth flagging: the video's Evolution section leans heavily on competitive multiplayer and speedrunning communities as evidence, which are genuinely hard to manufacture in a classroom setting (no live playerbase, no community discovering exploits) — so while the FRAMEWORK is sound, our own translation should be honest that "Evolution" is the weakest-fitting of the three categories for this class, more a nice-to-have (scoreboards, personal bests) than a real pillar, and that should be reflected in the batch write-up rather than presenting all three categories as equally actionable.

# Core Game Mechanics Explained – From Idea to Gameplay (RookieDev Part 2, 4.2 min)

**What it is:** The direct sequel to Part 1, narrowing in on "how to design a core mechanic" as a 5-step checklist, again narrated-slideshow style.
**Substance:** thin: even shorter than Part 1, restates the same "start simple, iterate, balance" advice as a numbered list with no worked example beyond one-line game references.

## Ideas, in the video's order
- [0:00:58] Start by asking what experience/emotion you want the player to feel (tension, mastery, freedom) before picking a mechanic (generic, but a legitimate ordering — feeling-first rather than mechanic-first).
- [0:01:27] A core mechanic is "an action played repeatedly"; must be easy to grasp but deep enough to stay engaging — too complex loses players, too shallow loses interest (generic).
- [0:01:55] Example: Katana Zero starts as simple slicing, later demands split-second dodge/kill timing — the mechanic's skill ceiling rises without changing its basic verb (a real, useful example of "same verb, rising skill ceiling").
- [0:02:25] A core mechanic should interact with other mechanics/world elements rather than exist in isolation, and should vary when combined with new tools/enemies (generic).
- [0:02:53] Playtest a rough prototype early; "if something feels off, tweak it" (generic).
- [0:02:53] Mechanics should reinforce the game's theme/identity: horror needs vulnerability mechanics (Alien Isolation's stealth/hiding), action needs fluid combo systems (Devil May Cry) (a real, useful pairing example).
- [0:03:23] Closing 5-step list: define the experience -> create a simple repeatable action -> add depth through interactions -> playtest/tweak -> make sure it supports the theme (generic checklist, restates the whole video).

## For our class (11-13, Minecraft mod, Gemini writes the code)
### Becomes something kids do
- **"Feeling first, then verb" spec sentence (5 min, part of a larger spec worksheet)**: before writing a mod-feature spec for Gemini, kid fills in one sentence: "I want the player to feel ___ when they ___." This is a small, genuinely useful ordering nudge (feeling before mechanic) buried in an otherwise thin video — worth lifting as a single sentence prompt, not a whole activity.

### Survives the move to Minecraft?
The "same verb, rising skill ceiling" idea (Katana Zero) and "mechanic matches theme" idea (horror = vulnerability, action = combos) both translate directly: a kid's mob attack or item ability can be checked against "does this fit the mood of where it's used" (e.g. a Nether-only status effect should feel dangerous, not cute).

### Doesn't transfer
The 5-step checklist as a whole is too close to restating "have an idea, test it, balance it" to be worth a dedicated worksheet — it would duplicate Part 1's and the MDA video's material for a 20-week course with limited class time.

## Honest caveats
This is the thinnest video in the batch by content-per-minute; almost every sentence is a truism about iteration and theme-fit that any of the other seven videos say with a sharper example. The one real idea (feeling before mechanic) is worth one sentence on a worksheet, not its own lesson. Don't mistake the 5-step list for a novel framework — it's the same "test/tweak/balance" loop every other video in this batch also states.

# Blockbench Texturing Tutorial for Beginners: Minecraft 3D Modeling (2026) (CountFrogg, 8.6 min)

**What it is:** Part 2 of the same CountFrogg beginner series — texturing (painting) the kiwi model built in part 1, covering paint mode, the paint bucket, hide/show elements, the color picker, a manual shading/blending technique, and straight-line drawing.
**Substance:** substantive as a how-to for the painting workflow specifically; like part 1, it teaches mechanics well but states zero design theory (no mention of palette limits, silhouette, or Minecraft's actual visual style) — it's purely "how to operate the paint tools," not "how to make it look good," despite one genuinely useful shading trick.

## Ideas, in the video's order
- [0:01:03] Switching from Edit mode to Paint mode changes the side panels from UV/Element to Paint-space/Color-space — a basic but necessary mode-switch fact for a first-timer.
- [0:01:35]-[0:01:36] Before painting anything, a texture file must be explicitly created via "Create Texture" (named "kiwi texture" here); a newly created texture is randomly colored by default until painted over.
- [0:01:36] The Create Texture dialog exposes a **Pixel Density** setting (visible in the frame, see below) plus toggles for "Keep UV," "Power-of-2 Size," "Keep Multi Texture Occupancy," and "Padding" — this is the direct control point for texture resolution the tutorial glosses over verbally but shows on screen.
- [0:02:09] Basic painting: pick a color from the palette, use the Paintbrush tool (B) to draw directly onto a UV-mapped face.
- [0:02:24]-[0:02:41] Paint Bucket tool has a **Fill Mode** dropdown with options Face / Element / Selected Elements / Connected Colors / Colors — set to "Face" fills one visible face at a time; set to "Element" fills an entire cube (all its faces) in one click. Explicitly taught as a speed shortcut over hand-painting each face.
- [0:03:14]-[0:03:20] To paint a part that's visually obstructed by another part (the whiskers were hidden behind the beak), go back to Edit/Element mode and use the per-element **visibility eye toggle** in the outliner to temporarily hide the obstructing cube (here: hide the beak to reach the whiskers underneath).
- [0:03:47] Eraser tool (E) used to clean up paint that bled onto unwanted faces — normal cleanup step, not a special technique.
- [0:04:23] **Color Picker tool (Alt)**: click any already-painted pixel on the model to re-select that exact color — explicitly framed as a fix for color-matching mistakes and a way to keep a palette consistent without manually re-picking a hex value.
- [0:04:32]-[0:04:54] Named "advanced technique": since Minecraft-style geometry can't be literally rounded, fake roundness/volume is created by making the bottom face of a cube darker and the top face lighter (basic top-down "fake lighting" via flat per-face shading) — an explicit acknowledgment that **cube geometry has a hard ceiling on smoothness, and shading is the workaround.**
- [0:05:04]-[0:05:27] Concrete shading/blending method: draw a straight line of the darker shade along the bottom edge as a "base," then explains the three brush parameters shown on screen — brush **size**, **opacity** ("how clear the color is"), and **softness** ("how much the brush sticks to the pixels": higher softness lets stray pixels scatter for a blended look, lower softness keeps edges crisp) — sets size/opacity/softness to 1/100/100 for this effect and paints a soft circular gradient into the corners to blend the two shades.
- [0:07:05]-[0:07:38] **Straight-line trick**: click once to place a starting dot, then hold Shift and click the end point — Blockbench auto-fills a perfectly straight line between the two clicks, taught as a precision technique for clean edges/stripes (demonstrated on the beak split-line and leg stripes).

## What the frames add

Multiple frames' window titles show the working texture canvas as **"32 X 32"** pixels (e.g. [0:01:52], and repeated UV-space thumbnails throughout Sheets 2-4) rather than a single 16x16 face — consistent with a standard Blockbench per-face UV unwrap needing a canvas that lays out multiple cube faces together (so a 16x16-per-face rule still holds per face, but the total image is larger). This is a real, visible pixel-density fact the video never states out loud and a class would need to explain explicitly. Sheet 1 [0:01:52] shows the actual auto-generated "random noise" texture Blockbench assigns to an unpainted UV map — a good visual for explaining why the "create texture" step is necessary before painting. Sheets 2-4 show the full progressive paint job on the kiwi (yellow beak, brown/tan body with darker-bottom/lighter-top shading, blue-tinted legs, purple eye dots, striped legs) — a clear before/after sequence useful as a reference for what's achievable in ~8 minutes of guided painting. The recurring host cutaways (green/purple textured wizard-kiwi humanoid) are the same pre-made "finished" example as part 1, reused as an aspirational bookend, not new content.

## For our class (11-13, Minecraft mod, Gemini writes the code)
### Realistic timeline and traps
Combined with part 1 (modelling), texturing a simple existing model adds roughly **another 45-60 minutes** of guided practice for an 11-13-year-old — the paint bucket (Face vs. Element fill) and basic brush painting are easy wins likely picked up in the first 15 minutes, but the shading/blending technique ([0:04:32]-[0:05:59], with its size/opacity/softness parameters) is a genuinely fiddly, trial-and-error skill that will take most kids several tries and produce inconsistent results without one-on-one guidance — budget it as an optional "polish" step, not a required one, for a first project.
- **Pixel density mismatch (the trap the brief asked about)**: the Create Texture dialog's Pixel Density setting is real and visible on screen but never explained — if a kid changes it away from Minecraft's native 16-pixels-per-block convention (e.g., picks a higher density "for more detail"), the resulting texture will look correct in Blockbench's preview but may render as blurry/scaled incorrectly or fail to match vanilla block/item texture conventions once in-game. This needs an explicit teacher rule ("always keep density matched to 16x16 per face") since the tutorial doesn't supply one.
- **UV mapping is invisible in this tutorial**: the video paints directly onto the 3D model's faces via Blockbench's "paint on model" convenience feature, so kids never have to think about the underlying 2D UV layout at all. That's good for approachability but means the class gets zero exposure to how UV unwrapping actually works or what to do if a custom/non-cube shape needs manual UV editing — flag as an open gap, not something this video teaches, if any kid's design needs anything beyond simple cube faces.
- **Face vs. Element fill mode confusion**: a real, observed trap — the tutorial itself has to explicitly stop and explain the Face/Element toggle in the paint bucket because it's not obvious from the UI alone; expect kids to accidentally fill only one face when they meant the whole cube (or vice versa) and to need this explained directly, not left to discovery.

### Becomes something kids do
- **Fake-roundness shading mini-exercise (15 min)**: dedicated practice on ONE simple cube — darker bottom, lighter top, blended corner — before applying it to a full mob. Comes from [0:04:32]-[0:05:59]; better taught in isolation first given how fiddly it is.
- **Palette consistency check using the color picker**: before painting a whole mob, have kids pick 2-3 colors from a reference image using the Color Picker tool and reuse only those (echoes the "2-4 colors" palette-discipline idea likely to recur elsewhere in this research) — a good bridge between this tool-literacy video and any design-theory material on palette limits.

### Survives the move to Minecraft?
Everything taught here (paint bucket fill modes, hide/show for occluded parts, color picker, straight-line trick) is native, format-agnostic Blockbench workflow that applies regardless of which model format is ultimately used for the NeoForge mod (see the companion modelling video's note on the Generic-vs-Modded-Entity format issue) — texturing technique itself doesn't change based on export format. The fake-shading-via-flat-shading technique is a genuinely Minecraft-appropriate workaround (since cube geometry can't actually curve) and is worth teaching explicitly as "how Minecraft artists fake roundness," tying back to the Mojang videos' own emphasis on working within the cube/pixel constraint rather than fighting it.

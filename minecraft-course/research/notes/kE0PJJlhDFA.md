# Minecraft Live 2022: Create Your Own Mob with Blockbench! (Minecraft/Mojang official, 3.1 min)

**What it is:** A short promo/demo segment from Minecraft Live 2022 introducing the "Entity Wizard," a Blockbench tool built in partnership with a named modder (Jannis/JannisX11) that lets players base a new mob on an existing vanilla mob's behavior, then reskin/reshape its look; includes short creator cameos (a toucan-inspired parrot reskin, a banana mob) and a YouTuber (Daniel Middleton/DanTDM) improvising a banana mob live.
**Substance:** thin-to-mixed: only ~3 minutes, heavy on enthusiasm and quick cuts between speakers, light on step-by-step detail — but it names a genuinely useful and specific workflow concept (archetype-based mob creation) not stated this clearly anywhere else in the batch.

## Ideas, in the video's order
- [0:00:00]-[0:00:30] The Entity Wizard's stated purpose: make it fast and easy to go from mob idea to in-game entity, explicitly designed so a beginner is "not really guessing" — you pick an existing mob as an **archetype** (e.g. "I want this to be like a bear") and build off it, rather than starting from nothing.
- [0:00:30]-[0:01:01] Stated design intent: the tool walks the user through steps, suggests options, and provides templates to pick from — framed as removing blank-page paralysis for first-time mob creators.
- [0:01:12]-[0:01:34] Case study from a Mojang staffer: wanted to recreate a real hornbill toucan, and deliberately chose to base it on the **parrot** archetype specifically because the parrot's existing gameplay behavior (flying, riding on shoulder, etc.) matched what she wanted the new mob to DO — explicit statement that **you choose the base archetype by matching desired BEHAVIOR, not just visual similarity**, then combining "what you want it to play/feel like" with "what it looks like."
- [0:01:34]-[0:01:47] Stated on-ramp for less confident users: **"if you're a scrubber... you can just start by painting an existing mob"** — i.e., reskinning texture-only is a valid, easier first step, and only once comfortable should you move on to changing the model's actual shape/dimensions.
- [0:01:47]-[0:02:07] Explicit encouragement to seek outside learning resources (official tutorials, Blockbench tutorials, YouTuber tutorials) and to look at what other people are making for inspiration before/while using the tool.
- [0:02:16]-[0:02:47] Live improvised demo (DanTDM): starts from a plain cube, stretches/shapes it into a curved banana silhouette using multiple small cubes at varying angles, then adds a simple pixel face; his own running commentary flags the real difficulty directly: **"How do you make a curved object in Minecraft? How does that work?"** — a genuine, unscripted acknowledgment that Minecraft's cube-based geometry makes curved/organic shapes hard, solved here only by stacking many small angled cubes as an approximation.

## For our class (11-13, Minecraft mod, Gemini writes the code)
### Becomes something kids do
- **"Pick your base animal" worksheet**: before any Blockbench work, kid names an existing vanilla Minecraft mob whose BEHAVIOR (not look) is closest to what they want their mob to do (flies? swims? passive? attacks? follows you?), and explicitly writes down what they're keeping (behavior) vs. changing (look). Directly from [0:01:12]-[0:01:34] — this is a strong, concrete worldbuilding-meets-mechanics bridge and gives Gemini a much more scoped, buildable spec ("make a mob that behaves like a parrot but looks like X") than an open-ended description.
- **Reskin-first permission**: explicitly tell kids it's fine (and expected, per Mojang's own "scrubber" framing at [0:01:34]) to start their FIRST mob as a texture-only reskin of an existing shape before attempting custom model geometry — lowers the bar for week-1 success and matches the class's realistic per-session time budget.
- **Curved-shape problem-solving mini-lesson**: show the banana build ([0:02:16]-[0:02:32]) as a live example of solving "how do I fake a curve out of cubes" (stack several small cubes at slightly different angles/offsets) — a concrete, memorable technique for any kid wanting an organic (non-blocky-looking) creature.

### Survives the move to Minecraft?
The archetype/base-mob concept is the most directly useful idea in this video for the class's actual constraints: since Gemini writes the Java behavior code, having a kid explicitly name "which existing mob's behavior is closest to mine" gives both the kid AND Gemini a much more concrete, buildable starting spec than free-form lore — this is arguably a better practical bridge between "3D design" and "game mechanics" (Ben's separate worry) than anything else surfaced in this batch, since it forces a kid to think about behavior and look together from the start, exactly as the class's spec-first workflow already intends.

### Doesn't transfer
The Entity Wizard tool itself is a Bedrock-Edition/Add-On-oriented tool (built for the archetype/behavior-pack pipeline) and is very unlikely to be usable as-is for a Java + NeoForge mod project — this needs to be flagged as an open question, not assumed: **do not promise kids "use the Entity Wizard," since its actual export target (Bedrock add-ons) likely does not match this class's Java/NeoForge stack.** The livestream promotional format (multiple creator cameos, on-stream banter, a "try it today" call to action) has no content value beyond the ideas already extracted above.

## Honest caveats
This is the thinnest and most promotional video in the batch (a 3-minute Minecraft Live segment), so treat its claims about ease of use ("super easy," "quickly make an entity") as marketing framing, not a neutral usability assessment — DanTDM's own on-camera struggle with curved shapes is more trustworthy evidence of real difficulty than the presenters' enthusiasm. The single most important open item from this video is unresolved and should not be guessed at: **whether the Entity Wizard (or any Bedrock-oriented Blockbench workflow shown here) has any real equivalent or export path for a Java/NeoForge mod** — this video never says, and nothing elsewhere in this batch confirms it either. No direct contradiction with the two CountFrogg tutorials, but note the format tension: CountFrogg's tutorials use plain Blockbench with a "Generic Model" (non-Minecraft) format; this video's Entity Wizard is a different, more guided, Bedrock-flavored tool entirely — the class needs ONE confirmed, tested, Java/NeoForge-compatible pipeline, and this batch alone does not establish which one that is.

# How to Train AI on Your Own Data Using Google Apps Script — Complete Tutorial | E37 (Mohammad Rameez Imdad, 9.0 min)

**What it is:** feature demo of a Gemini-powered chatbot widget embedded in an Apps Script web app, "trained" on data the owner types into a dedicated Sheet (not fine-tuning — retrieval/grounding via a lookup sheet). Includes a real API-key acquisition walkthrough and a glimpse of the actual backend code. No build-from-scratch prompting session shown, but directly on-topic for the "calling an AI API from Apps Script" ask.
**Substance:** mixed: the API-key walkthrough and the training-data concept are genuinely useful and directly relevant; the rest is a standard feature demo with heavy self-promotion.

## Ideas, in the video's order
- [0:04:58] "Train your data" mechanism explained concretely: a "Train Data" sheet has rows with a Category (e.g. "services you offer") and free-text Answer content; when a visitor asks a matching question, the chatbot's replies are grounded in those rows rather than invented — i.e., the "training" is really a lookup/context table fed to the Gemini API call, not model fine-tuning. Worth being precise about this distinction with the class (kids will assume "train" means changing the model itself).
- [0:01:06] Lead capture: the chatbot detects trigger keywords (price, cost, contact, "work with," "need help," etc., listed in a settings sheet) and pops up a lead-capture form mid-conversation, saving the submission to a Sheet and emailing a notification — a real trigger-word + form-injection pattern, understandable and buildable at a smaller scale (e.g., a class chatbot that flags "I need help" messages).
- **[0:07:08]-[0:07:40] Real Gemini API key walkthrough: go to `aistudio.google.com`, sidebar "Get API key," create a new key, free trial gives "$300 credit... enough for 3 months," no coding required to obtain it.** This is the clearest, most concrete "how do I even get a key" moment across the whole batch and should be reused near-verbatim for the course's own instructions.
- [0:07:40] Presenter explicitly avoids showing the API key on screen ("if we show the API key so we will get a strike") and scrolls past it — a real, if indirect, acknowledgment that the key must be kept secret, though the video never demonstrates the *correct* way to keep it secret (e.g. `PropertiesService`) — it simply avoids filming it (see traps).
- [0:08:13] Lead form only reappears "if your browser cache is cleared" — implies client-side state (e.g. localStorage or a session flag) gates re-showing the lead form, a real minor gotcha (testing the lead-capture feature repeatedly requires manually clearing site data).
- Generic: "10 languages supported" (a Gemini capability, not something built), "costs zero on hosting" (repeated marketing line).

## What the frames add
[0:06:40]-[0:07:00] show the actual **Apps Script code editor open with real backend code** (`exceptionHandler`, a role/tone lookup, sheet-reading logic) — one of the few videos to actually show working Apps Script source, though the API key call itself is scrolled past rather than shown. [0:03:40]-[0:04:30] show the "Roles" and "Train Data" configuration sheets side by side with the live chat, letting you see exactly how a typed row ("Category: services you offer / Answer: We offer...") maps to the AI's spoken reply — genuinely useful as a screenshot for teaching the grounding concept visually.

## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
Grounding an AI chatbot on a lookup/"training" sheet rather than true fine-tuning; obtaining a free Gemini API key at aistudio.google.com with the $300 trial credit; keyword-triggered lead capture; avoiding showing a secret key on screen (the right instinct, but no safe-storage mechanism demonstrated).

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
A "class FAQ bot" — kids fill a Sheet with Question/Answer-style rows about their own project or class, then wire a small Gemini call in Apps Script that answers using those rows as context — is a great, well-scoped AI-feature milestone once the basic CRUD skills are in place, and this video's Train-Data-sheet pattern is a ready-made template for it.

### Traps a kid will hit
The video demonstrates the *instinct* to hide a key from the camera but never shows *where the key should actually live in the code* — a kid copying this pattern would likely just paste the key directly into a `.gs` file as a string, which is exactly the trap CONTEXT.md wants flagged. The course must explicitly teach `PropertiesService.getScriptProperties()` (or Script Properties in the Apps Script editor UI) as the safe alternative, since no video in this batch shows it.

### Doesn't transfer, and why
Mostly transfers well (it's the right stack). The only non-transferable piece is scale: "10 free-form language support" and enterprise lead-routing are beyond a first project's needs.

## Honest caveats
Heavy self-promotion (asks for comments/likes/subscribes multiple times before showing content); the "secret trick that makes your chatbot 10x smarter" teased at the start is just the training-data sheet, not a separate trick — mild clickbait framing.

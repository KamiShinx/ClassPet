# Using Query Language: Select Custom Sheet Data as JSON (Laurence Svekis, 11.4 min)

**What it is:** third in the gviz/no-Apps-Script sequence (after `CtLRDP0jLNc`, `3QWzYqZd0w4`), teaching Google's SQL-like Visualization Query Language to filter/select data server-side via the URL.
**Substance:** substantive, and conceptually the most transferable video in the gviz sub-series — this is the clearest "the server can filter data for you" lesson in the batch.

## Ideas, in the video's order
- [0:00:00] Opens with the finished capability: `select A,E where E contains 'a' limit 3` — real SQL-like query embedded in the request URL.
- [0:01:39] Points to the official reference docs (developers.google.com/chart/interactive/docs/querylanguage) and explicitly compares it to SQL, telling students they can look up more clauses (where, group by, pivot, order by, limit, offset, label, format, options, from) — good "here's where the real docs live" moment, transferable research habit.
- [0:04:27] `encodeURIComponent(query1)` used to safely embed the raw query string (which contains spaces, commas, quotes) into a URL — a genuinely important, generic web-dev concept (URL encoding) taught concretely rather than abstractly.
- [0:07:45] Demos `select A,B where C > 100` — server-side numeric filtering, confirmed by editing the sheet's C values live and re-requesting to show the result set change.
- [0:08:52] Demos `where E contains 'a'` — string/substring filtering — and separately `limit 3` to cap result count. Explicitly frames these as parallel to SQL WHERE/LIKE/LIMIT.
- [0:11:00] Closing line ties it together: "the magic happens with your encodeURIComponent... a default JavaScript method... to specify the requests to the spreadsheet."

## What the frames add
Frames show the actual Google documentation page for the query language ([0:01:30]-[0:02:45]) — reusable directly as a link/reference for a kid who wants to go further. Later frames show the live sheet data next to the filtered/limited output ([0:07:30]-[0:11:00]), directly confirming the where/contains/limit demos match what's on screen.

## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
Server-side filtering/querying as a distinct, valuable idea from client-side JS filtering (do the work on the server, get back only what you need); URL encoding as a real necessity once query values contain special characters; the general shape of query languages (select/where/limit) as something that recurs across many real APIs and databases, not just this one.

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
A "leaderboard filter" mini-exercise: given a class scores sheet, build query strings that answer questions like "top 3 scores over 80" using `select ... where ... limit ...` entirely via URL params, no JS filtering logic needed — good, low-code way to make the query-language idea concrete and satisfying quickly.

### Traps a kid will hit
Forgetting `encodeURIComponent` and getting a broken/garbled URL once the query has spaces or quotes in it; mixing up single quotes vs backticks around string literals inside the query (he hits and fixes exactly this at [0:09:23]); assuming query language syntax is JavaScript (it isn't — it's Google's own SQL-like syntax, easy to conflate for beginners).

### Doesn't transfer, and why
Same limitation as the rest of the gviz sub-series: read-only, requires a publicly shared sheet, no write access — good for the "reading/filtering data" half of the course, not a general backend pattern for apps that also need to save data.

## Honest caveats
None specific — clean, focused, well-paced lesson; the shortest video in the batch and the most single-concept-focused, which likely makes it easier to teach as a standalone 15-20 minute segment.

## The ideas (in order, with [h:mm:ss])
- [0:34–1:06] **Passive onboarding**: a quick tour, 4–5 screens showcasing key features/tips, visuals matter a lot,
  always include a skip button. Jargon: **passive onboarding** = onboarding the user only watches, doesn't act in.
- [1:06–1:39] **Active onboarding**: a hands-on, step-by-step walkthrough of the app's primary task ("practice makes
  perfect") — more engaging, builds investment, but only works if the guided task is itself interesting.
- [1:39–2:11] **Tip onboarding**: unobtrusive tooltips attached to specific UI elements, shown only for non-obvious
  features; the balance to strike is not tooltipping the obvious stuff and not showing too many at once. Jargon:
  **tooltip** = a small pop-up box pointing at one UI element, usually with an arrow, that explains what it does.
- [2:11–2:46] **Checklist onboarding**: a short, achievable to-do list of setup steps the user checks off; keep it
  short — a long checklist feels overwhelming and gets abandoned.

## Vocabulary for prompting Gemini
- **Passive onboarding** → a swipe-through intro tour before the app opens → "add 3 intro screens with a skip
  button before the main app loads."
- **Active onboarding** → guiding the user through doing the real first action → "walk the user through creating
  their first task instead of just telling them how."
- **Tooltip** → a small labeled box pointing at one specific button/element → "add a tooltip pointing at the '+'
  button the first time the user sees an empty list."
- **Checklist onboarding** → a short crossable to-do list for setup → "show a 3-item checklist: add a name, pick an
  avatar, create your first item."

## Page material
- **Rules of thumb:** (1) name which of the 4 types your onboarding is before building it, don't mix them
  accidentally; (2) passive onboarding always needs a skip button; (3) active onboarding only works if the first
  real task is itself fun/fast; (4) tooltips are for non-obvious features only; (5) checklists must be short enough
  to actually finish.
- **Exercises:** (1) Look at 3 apps on your phone the first time you open them (or ask a friend to reinstall one and
  watch) — which of the 4 types is each one using? (2) Pick your own project and design a 3-step *active* onboarding
  for its single most important action (e.g. "tap here to roll the dice").
- **Quiz:** Q: Name the 4 types of onboarding. A: passive, active, tip, checklist. Q: What's the one rule that
  applies to every checklist onboarding? A: keep it short/achievable.
- **Game angle:** A browser game's first level *is* active onboarding if it walks the player through the core loop
  by playing it. A tip-onboarding tooltip pointing at the "roll" or "attack" button on turn 1 works well for a
  turn-based Apps Script game since there's no real-time pressure to rush past it. A checklist ("collect your first
  item ✓, open the shop ✓, save your progress ✓") is a natural fit for an idle game's first session. See
  Uf7xLHUpKHE for a much deeper, game-specific treatment of active/puzzle-style onboarding — pair the two.

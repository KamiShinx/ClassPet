# How to Use Gemini in Google Apps Script (Full Guide) (Peter's Google Tips, 4.3 min, whisper transcript)

**What it is:** a focused how-to for Google's **built-in Gemini side panel inside the Apps Script IDE itself** (not a separate chat, not a third-party tool). Recent (2025/2026 Workspace feature). Dense, no padding — closest thing in this batch to a real workflow + debugging documentary.
**Substance:** substantive: multiple real examples, an explicit constraints/rules section at the end, and — uniquely in this batch — an actual error being hit and fixed on camera.

## Ideas, in the video's order
- [0:00:22] Framing: Gemini is built directly into the Apps Script side panel — "reads your open file, grasps your goals, writes updates or fixes code right inside your Apps Script editor" — i.e., in-IDE, not copy-paste.
- [0:00:50] **Access requirement, stated explicitly**: needs "an eligible Google Workspace plan," and "your Workspace administrator must have Gemini features turned on in the admin console" — this is Workspace-admin-gated, not available to just anyone.
- [0:00:50] Opened via Extensions > Apps Script (from inside a Sheet) > the Gemini "spark" icon top-right of the panel.
- [0:01:19] **Example 1 — read/filter data**: prompt is "write a function that reads the invoices sheet, filters for rows where status is overdue, and logs the details." Gemini inserts code directly into the active editor using a **DiffView, with additions highlighted in green**; the human clicks "Accept" then hits Run — Gemini does not just paste text into the chat, it proposes an actual file diff.
- [0:01:49] **Example 2 — mail merge across services**: prompt asks Gemini to read names/emails where status is "pending," send a personalized email via Gmail per row, and update the status to "sent" — and notes Gemini's generated code **also handles not re-sending to the same client twice** (i.e., it added idempotency/dedup logic unprompted, going a bit beyond the literal ask).
- [0:02:16] First run of AI-generated code triggers the **standard OAuth authorization prompt** — same as every other video, reinforced as universal, not tool-specific.
- [0:02:46] **Example 3 — four-service orchestration**: iterate rows in Sheets, replace placeholders in a Google Doc template, export as PDF to Drive, email the PDF as an attachment — shown as one single generated multi-step function spanning Sheets/Docs/Drive/Gmail.
- [0:03:13] **The debugging moment, shown live and explicitly named "one-click debugging"**: running a script throws a red TypeError in the execution log; instead of manually reading the stack trace, the presenter clicks **"Fix errors with Gemini" right inside the console log**; Gemini reads the stack trace, explains the cause, and offers a corrected diff to apply.
- [0:03:40] **Explicit rules given at the end, worth treating as ground truth for how this tool behaves**:
  1. **File context is per-file**: "Gemini works on the currently open active file in your editor" — it does not see/edit other files unless told to.
  2. **All-or-nothing accept**: "proposed code changes are accepted or rejected as a single block" — no partial/line-by-line accept.
  3. **Cross-file references need an explicit URL**: "if you need to reference external files in your prompts, include their direct Google Drive URL."

## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
The clearest illustration in the whole batch of **AI-assisted debugging as a real loop**: run → read error → ask AI to explain and fix → review diff → accept → re-run. Also a strong, concrete example of cross-service backend orchestration (Sheets read → Docs template fill → Drive PDF export → Gmail send) as a single pipeline, useful when explaining "a backend does more than just store data — it can call other services in sequence."

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
Even though kids won't have this exact tool (see caveat below), **the three stated rules should become class rules for using plain gemini.google.com too**: (1) tell Gemini which file you're asking about (Apps Script + HtmlService means multiple files — kids must say "in Code.gs" or "in index.html" explicitly, since a chat-based Gemini has no notion of "currently open file"); (2) treat every AI code change as all-or-nothing — review the whole pasted block before replacing a file, don't assume you can cherry-pick; (3) when referencing another file's content in a prompt, paste it in explicitly (kids' Gemini has no Drive-URL access at all, so this is even more true for them). Backend concept taught: **reading a stack trace/error message and using it (not just the app's symptom) as the actual bug report you hand to the AI** — a mini-exercise: intentionally break a variable name, run, screenshot the red error, and paste *that* into Gemini asking for a fix.

### Traps a kid will hit
- The single biggest trap this video surfaces for OUR class specifically: **kids will not have this feature.** It requires "an eligible Google Workspace plan" with an admin who has turned Gemini on — personal Gmail accounts (which is what the kids are using, per CONTEXT.md) almost certainly do not have this side panel at all. Ben should not expect to see this UI in class; the realistic baseline is the copy-paste loop shown in 5iCcbsaRebA and mWHbwA_l_FM instead.
- All-or-nothing diff acceptance, if it *were* available, would still be a trap: a kid asking for one small fix inside a large generated diff has to accept the whole thing, including any unrelated change Gemini snuck in (as seen with the unprompted dedup logic in Example 2) — worth flagging as a general AI-pair-programming caution even without this tool.

### Doesn't transfer, and why
The entire in-IDE side panel — DiffView, inline "Fix errors with Gemini," Accept/Reject — is a paid-Workspace-only feature and, per the video's own stated requirement, needs an admin to enable it. **This is almost certainly not available to the class's personal Gmail accounts.** Do not plan any lesson assuming kids can open this panel; treat the *behavior rules* as transferable teaching points, not the tool itself.

## Honest caveats
This is the best single video in the batch for "what does AI-assisted building and debugging actually look like, concretely, including a real error and fix" — but its core value (the in-IDE panel) is very likely inaccessible to the class given personal Gmail accounts and the admin-gating the video itself states. Recommend using it as a *teacher-reference* for what a smoother version of the workflow could look like (and to describe to kids as "how professionals with paid accounts do this"), while building actual lesson plans around the copy-paste loop shown in 5iCcbsaRebA and mWHbwA_l_FM.

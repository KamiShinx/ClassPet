## Ideas, in the video's order
- [0:00:34]-[0:01:39] Three user roles (admin/partner/staff); adding a "daily ledger" entry that is optionally linked to a shipment/sale record, with a linked account's balance auto-recalculating — a real example of one write triggering a derived update elsewhere (generic backend idea, not explained mechanically).
- [0:02:11]-[0:02:45] Adding a shipment auto-computes total purchase from a formula (freight weight / 1000 x freight rate) — narrator states the formula explicitly, a good concrete "computed field" example.
- [0:02:45]-[0:03:18] Selecting a supplier auto-fills origin city/province from that supplier's record — a real foreign-key-style lookup, teachable as "pull related data instead of retyping it".
- [0:04:24] Adding a shipment expense auto-recalculates shipment profit/loss (sold − purchase − expenses) and writes a linked ledger entry — cascading updates across three views from one form submit.
- [0:06:29] Attempting a sale that exceeds available stock is blocked with "insufficient stock available" — the video's only shown validation/guardrail, worth noting as a concrete example of a business rule enforced before save.
- [0:08:11] Attempting to withdraw more than a partner's available profit share is blocked ("cannot withdraw more than available profit share") — a second concrete validation example, same pattern as above (cap a write against a computed ceiling).
- [0:08:45]-[0:09:49] A loan with an EMI count auto-generates a full installment schedule (10 rows from one form) — a genuinely good example of one input fan-ing out into many derived rows.
- [0:11:38]-[0:12:31] **Real, reusable deployment walkthrough**: "Make a copy" of the Sheet (copies bundled Apps Script code too) -> Extensions -> Apps Script -> Deploy -> New deployment -> set type "Web app", access "Anyone" -> Deploy -> Authorize access -> Advanced -> proceed anyway -> get the `/exec` URL. ## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
Computed/derived fields from a formula (freight cost); lookup-based autofill from a related record (supplier -> city); cascading recalculation across linked records (expense -> shipment P&L -> ledger); server-side validation blocking a write that would violate a business rule (stock, withdrawal cap); one input generating many rows (loan -> EMI schedule); the real Apps Script deploy sequence (Extensions -> Apps Script -> Deploy -> Web app -> Anyone -> Authorize).

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
A **class supply/points tracker**: giving out "points" or "credits" is blocked if it would exceed a fixed budget (mirrors the withdrawal-cap validation), and a linked "reason" record shows why a balance changed (mirrors the ledger-entry-per-transaction pattern). The deploy walkthrough itself is a ready-made first-week milestone: "make a copy of the starter Sheet, open the script, deploy it as a web app, get your own `/exec` URL."

### Traps a kid will hit
The two validation moments ([0:06:29] stock check, [0:08:11] withdrawal cap) are the clearest illustration in this video of a trap kids will hit constantly: forgetting to check a condition server-side before writing, and only validating in the UI. Worth pointing at directly. The deployment sequence itself previews real traps CONTEXT.md flags: the "Google hasn't verified this app" warning requiring "Advanced -> proceed" ([0:12:20]) will confuse first-time kids and needs to be pre-taught; and "new deployment" vs "manage deployments" (updating an existing deployment vs creating a fresh URL) is not distinguished in this video at all, which is itself a real Apps Script trap CONTEXT.md names (deployment versions) that this video glosses over.

### Doesn't transfer, and why
The entire commission-agent/trading domain (shipments, commodities, mandi ledgers, partner profit shares, supplier "Khata") is adult business bookkeeping specific to South Asian trading businesses, with no teen project mapping beyond the generic patterns already extracted above.

## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
Role-based access with a documented permissions table shipped in-app; denormalized convenience fields (room number carried onto appointment); auto-provisioning a login on record creation; a computed running balance with a status flag that flips on reaching zero and fires a side effect (email); unit-conversion inventory math; batch-generate-many-rows-at-once; and the one real trap — Apps Script functions need explicit authorization before they can run, surfaced as a confusing "no permission" error the first time.

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
The "balance hits zero -> auto status change -> side effect" pattern is a good small milestone: e.g. a class "chore tracker" where marking all chores done for a student flips their row to "complete" and (optionally) sends a `MailApp` email — teaches conditional writes plus a trigger-like side effect without needing real payments. The inventory unit-conversion math (box -> pack -> unit, decrement on sale) is a clean, scoped arithmetic exercise for an early lesson on reading/writing a single Sheet value correctly.

### Traps a kid will hit
The [0:14:18] authorization moment is real and worth pre-teaching explicitly: the first time any Apps Script function that touches Gmail/triggers/etc. runs, Google will block it until the script owner clicks through an "unverified app" authorization screen — kids will hit this and think their code is broken when it's actually a permissions step. Also worth flagging generically: any claim in this video about scale ("10,000-20,000 people, no lag") should not be trusted or repeated as an Apps Script/Sheets fact — Sheets-as-database has real read/write speed limits the video never engages with.

### Doesn't transfer, and why
Everything domain-specific (clinic roles, payroll, pharmacy inventory, invoices) is adult-business software with no teen-project pull, useful only as "look how many small forms one big system needs," not as a project shape to copy. The promised "prompts to build this yourself" are never shown or explained in the video itself (only teased as a description link), so there is nothing here to actually extract about how Claude Code was used, what broke, or how it was fixed.

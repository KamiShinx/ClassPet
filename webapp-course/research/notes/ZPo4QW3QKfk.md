# AJAX JavaScript Dynamic Quiz From Scratch with Sheets Data as JSON (Laurence Svekis, 118 min)

**What it is:** a from-scratch build tutorial (looks 2020-2021 era: classic Apps Script IDE with "Use classic editor" link, Materialize-free plain CSS). One continuous project: Sheet -> Apps Script JSON API -> vanilla-JS quiz game -> POST scores back to a second sheet.
**Substance:** mixed: the underlying build (doGet/doPost, deploy, fetch, DOM rendering, debugging technique) is genuinely substantive and directly on-target, but roughly 85% of the runtime is pure live typing/narration of what's being typed, including a ~14-minute detour (building a plain HTML table renderer) that gets thrown away once the "real" object-shaped JSON lands.

- [0:12:37]-[0:15:53] `getSheetByName`, `getDataRange().getValues()` returns nested arrays; `console.log` vs `Logger.log` (console.log dumps the whole object incl. methods -- he explicitly says avoid it, use Logger.log). Small but useful "which logger to use" tip.
- [0:16:26] Visual explainer card: laptop icon, JS+Sheets icons, arrow labeled "DATA", "Create a WebApp of Data" -- the clearest single-frame mental model in the video of "your script turns Sheet data into a served JSON endpoint." Reusable as a diagram beat in our own explainer.

- [0:25:47]-[0:39:56] Detour: builds a generic HTML `<table>` from the raw 2D array with a hand-rolled `maker(tag,parent,class)` DOM helper, manual `<th>`/`<td>` loops, then CSS striping/borders. Fully abandoned once the data is reshaped into objects at 0:41 -- teaches DOM basics (createElement/classList/appendChild) but is not reused code. **(generic, cuttable for our class)**
- [0:39:56]-[0:49:16] Reshapes the flat rows into `{question, answer, opts:[]}` objects server-side. Notable moment: he considers keying off the header row dynamically "in case somebody changes the spreadsheet headings" [0:44:54] then rejects it for hardcoded `row[0]`/`row[1]`/loop `i=1..5` indices "to have a more static way." **He flags the fragility himself and picks the fragile option anyway** -- a good talking point for class (why the dynamic version would have been safer).

- [1:12:45]-[1:16:56] "Next question" / remaining-questions counter / end-game trigger when `remaining === 0`; final report screen re-lists every question with the student's answer colored red/green.
- [1:23:07]-[1:24:56] First separate mini-lesson: two `<input>` fields + FormData POST to a *different*, standalone Apps Script project, just to prove doPost works before wiring it into the quiz.
- [1:26:19]-[1:41:15] The doPost debugging technique: writes a `tester()` function in the *same* script that manually builds a fake `e = {parameter: {...}}` object and calls the real handler logic against it, instead of redeploying and POSTing for every test. **This is the single most transferable "how AI-assisted building actually goes" lesson**: doPost can't be run/debugged directly in the IDE like doGet, so mocking the event object locally is the workaround.

## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
- Client vs server split: Sheet is the database, Apps Script's `doGet`/`doPost` are the API, the browser JS is the client fetching/posting JSON.
- Deployment identity: a Web app has a fixed exec URL but only serves whatever was in the **last deployed version** -- editing code alone changes nothing live.
- Access control at deploy time ("Execute as" / "Who has access") is what actually gates whether outside users can hit your endpoint.
- GET (read, no body) vs POST (write, FormData body, picked up via `e.parameter`) as the two request shapes a kid's whole app will ever need.
- MIME-typing a response (`ContentService.MimeType.JSON`) so `fetch().json()` on the other end parses correctly.

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
- **Milestone 1 -- "Sheet as API":** publish a doGet that returns a Sheet as JSON, view it raw in the browser. Teaches: reading Sheets, ContentService, deployment/access settings. (1 class session)
- **Milestone 2 -- "Read it into a page":** fetch that JSON into a page and render it as a list/table with Gemini-written JS (skip the hand-rolled `maker()` DOM-builder detour entirely -- let Gemini write `innerHTML` templates, which will take minutes not 14). Teaches: fetch, JSON parsing, basic DOM.
- **Milestone 3 -- "Class quiz app":** the full video's project, teen-scaled -- one team writes quiz questions into a shared Sheet, the app serves and plays them. Teaches: state machine (question index/score), event handling, styling feedback.
- **Milestone 4 -- "Send it back":** add a name+score doPost at the end, write results to a second sheet. Teaches: doPost, FormData, appendRow, and the mock-`e`-object debugging trick (have Gemini write a `tester()` helper before touching doPost blind).
- **Stretch -- "class poll/vote app":** swap the quiz for a one-question poll everyone submits to simultaneously; makes concurrency and "what happens when two people click submit at once" a live discussion (not covered in this video at all).

### Traps a kid will hit
- Forgetting to cut a **new deployment** after editing code, then insisting "my fix didn't work" when the live URL is just stale.
- Leaving "Who has access" at "Only myself," so the app works for the builder and 401s for every classmate testing the public link.
- The scary unverified-app OAuth screen on first run -- needs a guided "click Advanced, go to app anyway" moment or kids will simply stop.
- Copying the wrong Sheet ID (extra characters, wrong sheet tab) into `openById`, producing an opaque `SpreadsheetApp` error a 14-year-old won't be able to read.
- Hardcoding column positions (`row[0]`, `row[1]`, fixed option count) so relabeling/reordering a Sheet column silently breaks or mislabels the quiz -- the video's own creator flags and then walks into this trap.
- `e.parameter` (singular) only returns one value per field name; a kid sending an array-like field and reading `e.parameter` instead of `e.parameters` will lose data with no error.
- "It worked five minutes ago and now fetch just fails" -- the 1:54:45 incident is real and its cause was never fully nailed down; kids need to know "redeploy and hard-check the exec URL" as a default first troubleshooting step, not a last resort.

### Doesn't transfer, and why
- The ~14-minute hand-rolled `<table>`-from-scratch detour (manual `createElement`/`classList`/`appendChild` for every cell) -- with Gemini writing code, this whole segment is obsolete; a kid will get equivalent output from one prompt.
- Zero Teachable Machine / camera / microphone / any ML content -- not relevant to Ben's "AI apps" goal at all.
- No mention of quotas, concurrent writes, or Sheets-as-DB speed limits anywhere in 118 minutes, despite two people (or thirty) potentially hitting the same doPost in class at once -- a real gap for our concurrency teaching goal (see brief item 3).
- No CORS discussion even though the actual build is cross-origin (local file/DevTools fetching a script.google.com URL) -- he never hits a CORS error because Apps Script Web Apps don't enforce it against `fetch`, but our class should not assume that carries over unexamined to a Netlify-hosted final project without also covering doPost content-type quirks (Apps Script's POST handling is lenient in ways a "real" CORS-checked API wouldn't be).

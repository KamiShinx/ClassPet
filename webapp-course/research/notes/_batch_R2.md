# Batch R2 — Mohammad Rameez Imdad: AI-built business dashboards on Sheets + Apps Script

## What this batch actually is
15 short (6.7-19.8 min) videos from one channel that sells custom Apps Script/Sheets business dashboards. 13 of 15 are pure promo feature-tours of pre-built adult admin systems (wholesale, billing, payslip, cash book, fleet, appraisal, CRUD, trolley, job applications, HR/payroll) — click-through narration, essentially zero code or architecture explanation, most ending with "contact us on WhatsApp" or "334 projects available." One (X1FIciegIk0) is off-stack entirely — Google AI Studio/Gemini 3 "Build" mode, not Apps Script, and the narrator himself admits it can't do Sheets/Apps Script apps. One (VAd5nPj9cfM) is a channel-announcement video with almost no product content. **Be honest with Ben: this batch is weak on concept explainers and strong only as a source of architecture patterns inferred by watching the UI behave** — nothing here teaches client/server/database/API the way a tutorial would.

## Concept explainers worth reusing
- **Time-based triggers**, explained in plain English on-screen: owLVuq38oyo [0:03:52-0:04:57] ("Google Apps Script time-based triggers... Extensions → Apps Script → Triggers → add a time-driven trigger"). The single clearest explainer in the batch — usable near-verbatim.
- **Deploy sequence frames**: apysW3Qa8S4 sheet_003 and MdDB6a0vqDQ sheet_008 both show the actual make-a-copy → Extensions → Apps Script → Deploy → New deployment → "who has access: Anyone" → unverified-app warning → authorize screens, legibly. No video explains the "execute as me" vs "access: anyone" choice — Ben's class needs its own explicit lesson here since it's the single most consequential and confusing setting kids will face (apysW3Qa8S4 note).
- **Templates as data**: KZpi7bRU8j0 shows an actual sheet of email templates with placeholders, merged with real data and sent, plus a separate email log — the cleanest concrete example of string templating + a "definition table vs event table" distinction in the batch.

## Where videos agree / contradict
Agreement, strong and repeated across nearly every video: (1) one Sheet tab per entity, CRUD via modals; (2) a status field visualized as a pipeline (draft→sent→paid, pending→approved/rejected), (3) one user action cascading writes across 2+ sheets (convert quotation→invoice; PO received→stock updated), (4) a "type" field driving purely cosmetic/behavioral branching (invoice type, prize tier, theme color) — this exact shape recurs in 4 separate videos, strong enough to treat as a real, teachable pattern, (5) role-gated views, sometimes down to action-level not just screen-level (owLVuq38oyo), (6) file uploads → Drive → URL stored in a cell. No real contradictions between videos — it's the same template family reused across domains. One partial tension: reconciliation/recompute (YeSCYs6bNs0's "denormalized totals can drift, needs a manual recompute") is shown in exactly one video and never mentioned elsewhere, even though the same drift risk exists in every app with a running balance (loans in KrRFIwx_aXE, leave balances) — worth teaching as a general risk, not a one-off feature.

## What to cut
Nearly all business-domain vocabulary (commissions, purchase orders, appraisal workflow stages, payroll deductions) — none of it is a project a 14-year-old wants to build, and none of these videos explain the underlying mechanics well enough to be worth close reading beyond extracting the shape. Skip VAd5nPj9cfM almost entirely (channel-announcement filler) and treat X1FIciegIk0 only as a cautionary "this looks like an app but has no real backend" contrast case, not a build reference.

## Project seeds (translated to teen scale)
1. **Class raffle/ticket checker** (from OhuWKRS_pck) — public no-login lookup by name/number, admin awards prizes. Teaches: public read endpoint vs admin CRUD, hardcoded-vs-role-based auth check.
2. **Equipment/library checkout tracker** (from owLVuq38oyo) — QR-coded items, check-in/out log, daily email reminder for overdue items. Teaches: time-based triggers, camera/QR input to a row lookup, action-level roles.
3. **Suggestion box with teacher approval** (from apysW3Qa8S4) — submit → pending → approve/reject, per-record history. Teaches: approval workflow, audit trail — the cleanest, most stripped-down version of this pattern in the batch.
4. **Classroom points economy** (from YeSCYs6bNs0) — running balance per student, "recalculate everyone's balance" admin tool. Teaches: derived/cached totals, staleness, reconciliation.
5. **Club sign-up with templated confirmation email** (from KZpi7bRU8j0) — public submission form, templates-as-data, merge + send. Teaches: string templating, uniqueness validation, public-write-endpoint spam risk.
6. **"Only see your own stuff" journal/poll app** (from nD0IyJLKio4 / Sjxc1lgRY1w) — row-level visibility scoped to the logged-in user. Teaches: server-side filtering vs client-side hiding (the most repeated privacy trap in the batch).
7. **Simple shared drawing/whiteboard tool** (from iyoVs9UsHqI) — canvas app saved to Drive, listed and reopened by name. Teaches: not everything maps cleanly to Sheet rows; more fun/approachable than another CRUD table.

## Traps
- **Server-side filtering vs client-side hiding**: the most repeated real trap — shown implicitly across AbFbc615J9M, Sjxc1lgRY1w, nD0IyJLKio4. If Gemini fetches everything and hides rows in the browser, that's not privacy. Teach explicitly, early.
- **Plaintext-looking passwords in Sheet columns** (Sjxc1lgRY1w, OhuWKRS_pck frames) — any co-editor of the Sheet can read them. Needs an explicit "never store real passwords, hash or avoid" rule before kids add any login.
- **"Execute as" vs "who has access"** in the deploy dialog — never explained by any video, will break either "no-Google-account access" or "each student's own edits are attributed to them" if chosen wrong.
- **Hardcoded config values duplicated across files** (KrRFIwx_aXE's live on-camera fix of a hardcoded admin email in two files) — push kids toward a settings sheet instead.
- **New deployment versions**: none of the videos mention that editing code after first deploy requires a new deployment (or updating the existing one) or the live URL keeps serving stale code — the single most common Apps Script gotcha, absent from this whole batch, and worth teaching from scratch.
- **Camera-in-iframe risk confirmed first-hand**: owLVuq38oyo's narrator hits a live camera error during a QR-scan demo without diagnosing it — real evidence for the CONTEXT.md concern about webcam access inside Apps Script's sandboxed HtmlService iframe.

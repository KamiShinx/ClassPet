# Batch R4 — Mohammad Rameez Imdad (17 videos: AI-built business dashboards + "AI-powered web apps" playlist)

## Overview and honesty check
This batch is almost entirely **one channel's product-demo library**, not tutorials. Of 17 videos, only **2 show a real AI-build workflow on screen** (`k90Za3mjy20`, the Claude-Code + Netlify HR system, and `Hj78Zpgzapc`, Claude-in-Excel) plus one that shows a real AI *failure and recovery* (`yjAW62D0jcA`). The other 14 are click-through feature tours of pre-built templates — many end with "for custom projects, WhatsApp us" and paid-membership pitches. Several (`-CTai8cpzjA`, the "AI App Builder" in `G45uCnuRblE`, `Hj78Zpgzapc`) aren't even Google Sheets/Apps Script at all (PHP/MySQL, a closed SaaS builder, and Excel respectively) — flagged clearly in each note. Treat this batch as a source of **UI/feature ideas and a couple of load-bearing workflow lessons**, not as a library of build tutorials.

## Concept explainers worth reusing
- **Role-based permission grid** [`caqF3nVonIc` 0:00:00-0:00:20]: a literal on/off matrix (pages × roles) is the single clearest visual for explaining RBAC to a 14-year-old — reuse the screenshot even though the app itself is too complex to build.
- **"Approve and apply" gate before AI writes to real data** [`G45uCnuRblE` 0:01:07]: the best single safety habit in the batch. Directly reusable as a class rule: never let Gemini's proposed change take effect until you've said out loud what you expect it to do.
- **doPost + async delay + where files land** [`k90Za3mjy20` 0:12:02]: presenter correctly explains that a selfie upload takes 3-5 seconds because it's "using the doPost function," with the image saved to Drive and the row saved to Sheets separately — a rare, accurate plain-language explanation of client/server round-trip and where different data types end up.
- **Free key acquisition, step by step** [`-9oe8rSy714` 0:07:08]: aistudio.google.com → sidebar "Get API key" → $300 free trial ("enough for 3 months") — the clearest walkthrough to reuse verbatim for the course's own key-setup instructions.
- **Formula-as-text vs. direct-edit** [`yjAW62D0jcA` 0:03:57]: AI returning a formula for a human to verify and paste, versus AI editing data directly — a good safety spectrum to teach explicitly.

## Project seeds (teen-scale, tagged by backend concept)
1. **Class store with live stock** (`oBkgL2iQygA`) — buying an item deducts from a Products sheet in real time. *Teaches: read-then-write, single source of truth.*
2. **Class treasury with approval** (`9RTuGIonXe0`, `qYlqj_r9Qsg`) — a student submits an expense, a second "treasurer" role approves it before it counts; add a budget-limit check as a stretch goal. *Teaches: two roles, a pending/approved state machine, guarding a write with a stored limit.*
3. **Bake-sale cart with bulk pricing** (`MQIG1VMifCo`) — price per item drops past a quantity threshold. *Teaches: applying a rule to a live number before computing a total.*
4. **Fantasy crypto/stock game using `GOOGLEFINANCE()`** (`UsowwR3xt_c`) — real live prices with zero API key needed. *Teaches: reading external live data as a warm-up before a real API.*
5. **Class help desk with auto-routing** (`5pH1DgDP-rY`) — a submitted problem auto-assigns to whichever "helper" role covers its category. *Teaches: category-to-assignee rule, a second harder pass being round-robin fallback.*
6. **Class FAQ / "ask about our project" bot** (`-9oe8rSy714`, `caqF3nVonIc`) — kids fill a Question/Answer sheet, then a small Gemini call answers visitor questions grounded in those rows, scoped so the bot never sees more than the asker is allowed to. *Teaches: AI grounded on your own data, permission-scoped AI access — a stretch/final-project feature.*
7. **Selfie/photo check-in via a Netlify-hosted frontend** (`k90Za3mjy20`) — directly mirrors the course's own final-project plan (frontend off Apps Script for camera access, talking to the backend over `doPost`/JSON). *Teaches: the entire client-hosted-separately-from-backend pattern the course needs for its final project.*
8. **Cascading "pick a category, see filtered options" dropdown** (`EpTg3bXyG_k`, `OtEA3awt0NU`) — small, one-lesson, teaches a lookup-table pattern without any of the source templates' complexity.

## Traps (Apps Script / AI-building problems, and which a kid will hit)
- **Plaintext passwords everywhere.** Confirmed on screen in at least 4 videos (`_tFUWkaC4RM`, `EpTg3bXyG_k`, `UsowwR3xt_c`, `qYlqj_r9Qsg`) — Login sheets store passwords as plain readable text, and in `UsowwR3xt_c` the Apps Script code compares them with plain `===`. This is the single most consistent, most copyable bad habit across the whole batch and needs an explicit early-course warning: **anyone with edit access to the Sheet can read every password**, full stop.
- **API key stored as a plain setting value, never in Script Properties.** Every video that wires up a Gemini/ChatGPT key (`caqF3nVonIc`, `9RTuGIonXe0`, `-9oe8rSy714`, `MQIG1VMifCo`) pastes it straight into a settings field or `.gs` file. `-9oe8rSy714` even shows the presenter's own instinct to hide the key from the camera ("we will get a strike") — the right impulse, but no video ever demonstrates `PropertiesService.getScriptProperties()` as the actual fix. **This is a gap the course must fill itself**, since no source video does it.
- **Forgetting a one-time setup/seed step after deploying.** `k90Za3mjy20`'s real, unstaged failure: first login after deploying fails because demo data was never seeded; the fix is to run a `setupDemoData()` function from the Apps Script editor. A kid is very likely to hit this same class of bug (something isn't initialized) and should be pre-taught "if the very first thing you try after deploying fails, check for a missed setup step" as a first debugging reflex.
- **AI losing track of which sheet/tab it's acting on.** `yjAW62D0jcA`'s real failure: a repeat command silently does nothing until the sheet is reselected — the presenter's own words, "sometimes it make mistakes... it will make definitely error," are the most candid admission of AI unreliability in the batch.
- **Naive race conditions in stock/count deduction**, never surfaced by any source video (`oBkgL2iQygA`'s stock deduction, for example) — the course needs to add the "what if two people click buy at the same time?" discussion itself, since none of these videos raise it.
- **Clicking through destructive AI permission prompts.** `Hj78Zpgzapc` shows a real "potential data loss, clear range A1:Z100" warning, immediately overridden with "dangerously always allow" — a vivid, filmable cautionary clip (wrong platform, but the lesson is platform-agnostic) for the very first lesson on AI permission prompts.
- **Camera/mic blocked inside the Apps Script iframe, confirmed in practice** — `k90Za3mjy20` only gets working camera+GPS because the frontend is hosted on Netlify, exactly validating CONTEXT.md's stated plan; no video in this batch shows camera access working from inside a pure Apps Script HtmlService page.

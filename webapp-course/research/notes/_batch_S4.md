# Batch S4 — Laurence Svekis, Apps Script channel (8 videos)

**Theme note:** despite the batch label mentioning "Docs/Forms/email automation," none of these 8 videos are actually Docs/Forms/email content — say so plainly. All 8 are Sheets-and-web-app material: one is a promo trailer (i-xz34p-hvM), one is Sheets-UI-only with no web app at all (MXuuvK2uU3o), and the other six form two connected mini-courses: a bound-script UI course (2E9RiYrNkwM continuing MXuuvK2uU3o) and a genuine six-part "build a Sheets-backed JSON API and consume it" course (i-xz34p-hvM intro -> 0aNN8MHdv_w -> frejbw3eJTY -> JOOUtlOKbak -> AfA8twIVxRg -> 8VKh6WdY-qc). The second course is the strongest material in the batch by a wide margin for this class's goals.

## The strongest ideas for this class

1. **The doGet/deploy/JSON pipeline, taught as one continuous arc across four videos, is the best material in the whole batch.** 0aNN8MHdv_w explains `doGet` and walks the full deployment dialog (type, execute-as, access level) with legible screenshots of every step; frejbw3eJTY shows reshaping raw Sheet rows into JSON via `ContentService`; JOOUtlOKbak closes the loop with a genuinely separate frontend (`fetch`) consuming that JSON — architecturally the closest thing in the batch to the class's planned final-project shape (Netlify frontend + Apps Script backend). Recommend building the first several class sessions' spine directly around this sequence rather than around any single video.
2. **The exec-vs-dev URL distinction and "redeploying doesn't update your old URL" trap** (0aNN8MHdv_w [0:12:10], confirmed again in frejbw3eJTY [0:10:15]) is explained clearly and is exactly the kind of thing that will otherwise eat a whole class session in "why isn't my change showing up" confusion. Worth a dedicated 5-minute class explainer early on, reusing this framing almost verbatim.
3. **`google.script.run` / `withSuccessHandler` (2E9RiYrNkwM) and `fetch().then()` (JOOUtlOKbak, AfA8twIVxRg, 8VKh6WdY-qc) are the batch's two async request/response patterns.** Worth explicitly teaching them side by side as "the same idea, two different APIs" — `google.script.run` only works inside a bound Sheets UI and won't carry over to the Netlify final project; `fetch` is the one that will. The batch itself never states this distinction; it's an inference worth making explicit to avoid kids thinking `google.script.run` is what they'll use all year.
4. **The array-of-arrays -> array-of-objects reshape** (taught fully in frejbw3eJTY, reinforced with a harder, sparse-data version in AfA8twIVxRg) is a genuinely reusable "why can't I just send the raw Sheet" teaching moment and a good guided-coding kata: hand kids a small sheet, have them predict the JSON shape before writing/generating any code.
5. **Real, unedited bugs caught on screen** (frejbw3eJTY's empty-array index bug, AfA8twIVxRg's off-by-one loop bounds, 8VKh6WdY-qc's property-name mismatch and a real `classList.add('')` DOMException) are more valuable teaching material than any of the clean final code, because they model exactly the kind of error a kid using Gemini will hit and need to read a console error message to fix. Worth pulling these into a short "read the red text" debugging-literacy exercise early in the course.
6. **The OAuth "Google hasn't verified this app" consent screen appears in four separate videos** (MXuuvK2uU3o-adjacent 2E9RiYrNkwM, 0aNN8MHdv_w, AfA8twIVxRg). It's real and unavoidable for every kid's first script run of the year — worth pre-empting explicitly on day one so nobody panics or thinks they broke something.

## Where videos agree or contradict

- **Agree:** every deployment-focused video (0aNN8MHdv_w, frejbw3eJTY, AfA8twIVxRg) treats "Anyone" access + "Execute as: me" as the default classroom-appropriate setting for a shareable endpoint — consistent and fine for kids' Sheets-as-database projects (no sensitive data expected).
- **Contradiction/gap worth flagging in class:** 0aNN8MHdv_w teaches server-side templating (`<?= myStr ?>` baked into HTML at request time via `HtmlService`), while frejbw3eJTY/JOOUtlOKbak/quiz pair teach client-side fetching of a separate JSON endpoint (`ContentService`). The batch never contrasts these two patterns explicitly, but they represent genuinely different architectures (server renders vs. client fetches). Worth explicitly teaching both exist and naming which one the class will standardize on for the final project (client fetches, since that's what a Netlify-hosted frontend requires).
- **Gap, not contradiction:** none of the six JSON-course videos ever mention CORS, even though JOOUtlOKbak's whole premise is a separate origin (localhost via Live Server) successfully calling the deployed Apps Script URL. It works there because of the specific "Anyone" access setting and Apps Script's default headers, but the videos give no framework for diagnosing CORS failures — a real risk once the final project moves to Netlify. This needs a standalone explainer built separately; don't assume any video in this batch covers it.
- **MXuuvK2uU3o and 2E9RiYrNkwM** (the bound-script UI pair) are a genuinely different track from the JSON-API pair: alerts/prompts/modals/sidebars inside the Sheets UI itself, no deployed URL at all. Useful only as an Apps Script syntax/trigger warm-up (menus, `onOpen`, UI objects) — don't present them to kids as "building a web app," since they aren't one.

## Project seeds (3-8 ideas, teen scale, tagged with backend concept)

1. **Class trivia/quiz app** (direct lift from AfA8twIVxRg + 8VKh6WdY-qc): kids design their own quiz Sheet, build the `doGet`/JSON endpoint, then the playable front end with scoring. Teaches: reading Sheets as an array, reshaping to objects, `ContentService`/JSON responses, `fetch`, DOM rendering, basic game state.
2. **"Load sheet data" live list** (from JOOUtlOKbak): any personal-interest Sheet (favorite games, pets, playlists) rendered as a styled, re-fetchable list with a "Load Data" button. Teaches: `fetch`/JSON parsing, conditional styling from data, avoiding duplicate-render bugs.
3. **Class poll/scoreboard app**: a Sheet that acts as shared storage; a page reads current results via `doGet`/JSON (writing rows would need a `doPost`, not covered in this batch — flag as a gap to teach separately). Teaches: reading rows back, "live" data with no caching, multiple users viewing the same backend.
4. **Sidebar add-on toolkit** (from 2E9RiYrNkwM): a personal Sheets sidebar with buttons that read/write sheet cells via `google.script.run`. Lower priority (doesn't transfer to the Netlify final project) but a good low-stakes first taste of client/server split before `fetch` is introduced. Teaches: client-vs-server split, async callbacks, DOM updates from server data.
5. **"Reveal my data" personal API**: kids build a Sheet about themselves (favorite things, stats) and deploy it as a JSON endpoint they can proudly share the raw JSON URL for. Teaches: deployment flow, access levels, what a URL-addressable API actually is, in the simplest possible form.
6. **Sparse-data survey form** (from AfA8twIVxRg's variable-length-answers pattern): a Sheet where not every row has the same number of filled columns (e.g., some students answered 2 questions, others answered 4), and code that safely skips blanks. Teaches: handling irregular/sparse data from a spreadsheet, defensive coding around missing values.

## Traps (Apps Script / AI-building problems a kid will hit)

- **Deployed code not updating** — editing `.gs`/HTML and refreshing the old `/exec` URL shows nothing new until redeployed; and redeploying via "New deployment" (rather than updating an existing one) silently changes the URL. The single most likely source of "it's broken!" confusion all year; teach explicitly and early.
- **OAuth consent wall** on every first run of a new project, worded scarily ("Google hasn't verified this app") — expect it, don't panic, click through Advanced.
- **Scriptlet escaping** (`<?= ?>` vs `<? ?>` vs `<?!= ?>`) is a subtle syntax Gemini could get subtly wrong with no error message, just wrong-looking output (0aNN8MHdv_w).
- **Off-by-one / index bugs when scanning a fixed range of optional spreadsheet columns** — happened live in two different videos in this batch (frejbw3eJTY, AfA8twIVxRg); very likely to recur in Gemini-generated code handling similar sparse data.
- **Forgetting to clear old rendered content before re-rendering** — causes visually duplicated/stacked output on a second fetch or replay (JOOUtlOKbak, 8VKh6WdY-qc); a classic no-error, just-wrong-looking vibe-coding bug.
- **Forgetting to remove/disable old event listeners before adding new ones** — causes double-registered clicks across re-renders (8VKh6WdY-qc's `removeClicks()` pattern is the fix, worth teaching as a named pattern).
- **No CORS coverage anywhere in this batch** despite one video (JOOUtlOKbak) depending on cross-origin fetch working — a real, unaddressed gap for the class's Netlify final project; build a separate explainer.
- **Confusing `google.script.run` (Sheets-bound only) with `fetch` (works anywhere)** — the batch never distinguishes them; a kid could reasonably assume both generalize to the final project when only `fetch` does.

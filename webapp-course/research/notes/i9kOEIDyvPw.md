# How to Build a POS System for Small Business – Claude Code + VS Code + Google Sheets (Mohammad Rameez Imdad, 11.6 min)

**What it is:** hybrid tutorial/promo. First ~4 minutes are a real, screen-recorded build sequence (install the Claude Code VS Code extension, open a folder, paste one long prompt, Claude generates code, copy into Apps Script, deploy, authorize, seed demo data); the remaining ~7.5 minutes are a click-through feature tour of the finished wood-trading POS, same format as this channel's other demo videos.
**Substance:** mixed. The build sequence is genuinely useful (this channel's only video in the batch that actually shows AI-assisted building on screen), but it is compressed into one giant one-shot prompt with zero visible errors, debugging, or iteration — not representative of what a "weak, forgetful AI" workflow with a class of 14-year-olds will actually look like.

## For our class (14-15, Gemini writes the code, Apps Script + Sheets)
### Backend concepts it shows or explains
The real two-file split (server `code.js` + client `index.html`) and the exact deploy/authorize dance (Web app -> Anyone -> Deploy -> unverified-app warning -> Advanced -> proceed) match what kids will do every time they publish; a reusable `setupDemoData`-style reset function; stale-while-revalidate caching named as a concept; a permission matrix as in-app documentation; a customer-style running ledger.

### Becomes something kids do (activity, mini-project, milestone), concrete enough to run next week
Use the deploy sequence shown here almost verbatim as a step-by-step class walkthrough for "publish your first Apps Script web app" — it is accurate and matches current Apps Script UI. Have every kid build one small utility function early (like `setupDemoData`) that wipes and reseeds their own Sheet with sample rows, so they can reset a broken project instead of hand-fixing corrupted data — directly useful against CONTEXT.md's "AI nukes working projects" risk. A simple "duplicate this row as a new draft" button (copy an existing form's values in) is a small, scoped exercise in reading a row and pre-filling a form.

### Traps a kid will hit
The authorization sequence ("Google hasn't verified this app" -> Advanced -> proceed anyway) is confusing and looks like an error the first time; walk through it once as a class so nobody thinks they broke something. The video's "one big prompt builds everything" framing is the opposite of what CONTEXT.md warns about — a free/weak Gemini model asked to one-shot a multi-role POS with OTP and PDF invoices will very likely hallucinate or silently drop features; kids should be taught to ask for one small piece at a time and check each step, not copy this video's scale of ask.

### Doesn't transfer, and why
The tool itself (VS Code + the Claude Code CLI extension, logging into a paid Claude account) is not what kids will use — they work in the Gemini web app and paste into the Apps Script editor directly, so the extension-install and in-editor chat-panel steps have no direct equivalent. The domain (wood trading, OTP reset, supplier/customer ledgers) is adult small-business software with no teen-project pull; keep only the deploy mechanics and the reset-function idea, discard the business framing.

## Honest caveats
This is the more honest of the two videos in this pair, but it is still a compressed highlight reel, not a real build log: zero errors, zero corrections, and a scope (role-based auth, OTP, PDF/A4 invoices, bulk CSV import, SWR caching) that is very unlikely to have come from one untouched prompt with no follow-up fixes — the "few minutes, one prompt" claim at [0:00:00] should be treated as marketing, not a literal account of the build. The full text of the prompt itself is never shown on screen (only referenced as "link in the description"), so we cannot evaluate its structure or size, only that a prompt existed and Claude produced two files from it.
